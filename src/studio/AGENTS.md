# Studio (private back office)

Governing specs: [0003 studio placement and stack](../../docs/specs/0003-studio-placement-stack/index.md), [0005 studio login](../../docs/specs/0005-studio-login/index.md), [0006 client tracking](../../docs/specs/0006-client-tracking/index.md), [0007 contracts and PDF export](../../docs/specs/0007-contracts-pdf-export/index.md), [0008 private systems map](../../docs/specs/0008-private-systems-map/index.md), [0010 lead intake](../../docs/specs/0010-lead-intake/index.md), [0013 invoicing](../../docs/specs/0013-invoicing/index.md). The studio is a gated `/studio` area inside this app, shipped in the same Vercel deploy as the public site.

## Where things live

- Client data retention follows [spec 0011](../../docs/specs/0011-client-data-retention/index.md), the explicit exception to the ordinary archive only client lifecycle.
- `src/studio/retention/`: `rules.ts` holds policy constants, eligibility, filters and consent validation; `service.ts` owns scoped snapshots, holds, previews, removal, receipts and metadata cleanup; `actions.ts` guards posted forms and redirects.
- `src/app/(studio)/studio/(signed-in)/retention/`: policy and filtered list, `[kind]/[id]/` review and holds, `previews/[previewId]/` confirmation, and `receipts/[eventId]/`. Shared forms and record paging live in `_components/`. The client detail page links to retention review.

- `src/studio/guard.ts`: two gates. `requireStudioEnabled()` checks the flag only (`notFound()` unless `STUDIO_ENABLED === "true"`). `requireStudioAccess()` checks the flag plus the owner session, redirects to `/studio/login?next=` when signed out, and returns the `StudioSession`.
- `src/proxy.ts`: Next 16 proxy, matcher `/studio` and `/studio/:path*`. Returns a bare 404 when the flag is off, redirects to the login page when the session cookie is missing (except on `/studio/login` and `/studio/setup`), sets the `x-studio-pathname` header, and refreshes the session cookie on GET requests only. It never touches the database. A first filter only, never the real gate.
- `src/studio/auth/`: owner passkey login (SimpleWebAuthn v14) with opaque, hashed database sessions (30 days, sliding). `actions.ts` (server actions: sign in, setup, sign out, sign out everywhere, add passkey), `session.ts` (`getStudioSession()`), `config.ts` (constants and `getRpConfig()`), `challenge.ts`, `passkeys.ts`, `owner.ts`, `events.ts` (auth events, kept 90 days), `safe-next.ts`, `device-label.ts`, `cookie.ts` (cookie names, attributes, and the path header).
- `src/app/(studio)/layout.tsx`: studio root layout (own `<html>`, no Header, Footer, or Analytics, robots `noindex, nofollow`, `force-dynamic`). Every `/studio/*` response, route handlers included, also gets an `X-Robots-Tag: noindex, nofollow` header from `next.config.mjs` (spec 0009).
- `src/app/(studio)/studio/(auth)/`: the login and setup pages (flag gate only). `src/app/(studio)/studio/(signed-in)/`: everything behind the session, with its own layout calling `requireStudioAccess()`; `page.tsx` is the shell with the status lines, `security/` holds add another passkey. Shared client pieces live in `src/app/(studio)/studio/_components/`.
- `src/app/(studio)/studio/(signed-in)/clients/`: client tracking (spec 0006). The list (`?q=`, `?status=`, `?archived=1`, `?page=`), `new/`, and `[clientId]/` with `edit/`, `contacts/`, `projects/`, `notes/` routes, one route per form, plus `loading.tsx`, `error.tsx`, `not-found.tsx`. Form pieces live in `_components/` (`Field.tsx`, `FormMessage.tsx`, `FormPage.tsx`, `ConfirmSubmit.tsx` over the shadcn `AlertDialog`, the per entity forms, `ui.ts` class strings).
- `src/app/(studio)/studio/(signed-in)/contracts/` and `templates/`: contracts and templates (spec 0007). The contract list (`?status=`, `?archived=1`, `?page=`), `[contractId]/` (page, `edit/`, and the `pdf/` and `files/[fileId]/` route handlers), the template list, `new/`, and `[templateId]/edit/`. New contracts start at `clients/[clientId]/contracts/new/`. Contract pieces in `_components/`: `ContractBody.tsx` (the shared preview), `TemplateForm.tsx`, `ContractForm.tsx`, `StepDialog.tsx`, `SignedCopyInput.tsx`, `AddSignedCopyForm.tsx`, `Paging.tsx`.
- `src/studio/contracts/`: `placeholders.ts` (the only allowed `{{…}}` names and their labels), `markdown.ts` (the Markdown subset parser), `values.ts` (placeholder values from their rows), `pdf/render.tsx` (`renderContractPdf()` over `@react-pdf/renderer`, with the Noto Sans TTFs and OFL license in `pdf/fonts/`), `file-response.ts` (headers for every file response), `actions.ts` (contract and template server actions).
- `src/studio/data/contracts.ts`, `contract-templates.ts`, `contract-files.ts`: contract reads and writes, templates, and the append only file rows. `storage/blob.ts` adds `putPrivatePdf()`, `getPrivateFile()`, `deletePrivateFile()`.
- `src/app/(studio)/studio/(signed-in)/invoices/`: invoicing (spec 0013). The list (`?status=` including the derived `overdue`, `?archived=1`, `?page=`), `profile/` (the billing profile), and `[invoiceId]/` (page, `edit/`, and the `pdf/` route handler). New invoices start at `contracts/[contractId]/invoices/new/`. Form pieces in `_components/`: `InvoiceForm.tsx`, `InvoiceRows.tsx`, `InvoiceStepDialog.tsx`, `BillingProfileForm.tsx`.
- `src/studio/invoices/`: `money.ts` (quantity and peso parsing, line amounts, totals), `actions.ts` (invoice and profile server actions), `read.ts` (`invoiceRead()`, which wraps every invoice read so a failure throws only a fixed operation name and code), `pdf/render.tsx` (the invoice layout, reusing `registerPdfFonts()` from `contracts/pdf/render.tsx`).
- `src/studio/data/invoices.ts`, `invoice-numbers.ts` (`peekNextNumber()`, `takeNumber()`, `formatInvoiceNumber()`), `invoice-files.ts`, `billing-profiles.ts`: invoice reads and writes, the per year number counter, the frozen PDF rows, and the one profile per workspace.

The board (`?archived=1`) with the drift banner, `new/`, `import/` (paste the artifact JSON, preview, apply), the `export/` route handler (downloads `products-data.ts`), and `[systemId]/` with `edit/`, `links/`, `resources/`, `notes/` routes. Form pieces in `_components/`: `SystemForm.tsx`, `SystemImportForm.tsx`, `SystemLinkForm.tsx`, `SystemResourceForm.tsx`, `system-labels.ts` (layer and status labels).
- `src/studio/systems/`: `actions.ts` (system, link, resource, note, and import server actions), `import.ts` (`parseImportJson()`, `planImport()`, `readImportState()`, `applyImportPlan()`), `import-state.ts` (the import's `ActionState` with `plan` and `counts`), `projection.ts` (`getPublicProjection()`, the only query that feeds the export and drift), `export.ts` (`buildPublicProductsFile()`, pure), `drift.ts` (`diffPublic()`, pure), `bundled.ts` (the one relative import of `utils/data/products-data`, since `@/*` maps only to `src/*`).
- `src/studio/data/systems.ts`, `system-links.ts`, `system-resources.ts`: systems map reads and writes, with `lockLiveSystem(tx, id)`; system notes live in `notes.ts` beside client notes.
- `src/app/(studio)/studio/(signed-in)/inquiries/`: the inquiry inbox (spec 0010). The list (`?status=`, `?alert=`, `?page=`), `[id]/` (detail, status changes, alert retry), and `[id]/convert/`, plus `loading.tsx`, `error.tsx`, `not-found.tsx`. Form pieces in `_components/` (`MutationForm.tsx`, `ConversionForm.tsx`).
- `src/studio/inquiries/actions.ts` and `src/studio/data/inquiries.ts`: inbox server actions and reads and writes (`listInquiries`, `getInquiry`, `changeInquiryStatus`, `convertInquiry`). The public intake side lives in [src/inquiries/AGENTS.md](../inquiries/AGENTS.md), which reuses `db/client.ts`.
- `src/studio/clients/`: `actions.ts` (the client, contact, project, and note server actions), `action-state.ts` (the `ActionState` result type, plain types so client forms can import it), `list-params.ts` (list URL parsing and links), `page-errors.ts` (`notFoundOr()`).
- `src/studio/data/clients.ts`, `contacts.ts`, `projects.ts`, `notes.ts`: client tracking reads and writes. `input.ts` parses form input (trim, blanks to null, lengths, formats, dates) into one `InvalidInput` with `fieldErrors`. `errors.ts` holds every coded error plus `pgErrorOf()` and `isUniqueViolation()`.
- `src/studio/format.ts`: `STUDIO_TIME_ZONE` (`Asia/Manila`), `formatDate`, `formatDateTime`, `formatPlainDate` (date columns, no day shift), `statusLabel`, `formatAmount` (centavos as `PHP 12,500.00`), `amountInputValue`, `slugify` (file names).
- `src/studio/data/workspace.ts`: `getWorkspaceId()` reads the workspace from the session and throws `NoWorkspaceScope` when there is none (never a constant fallback). `runInWorkspace()` is for scripts only (the seed); request code never calls it.
- `src/studio/db/client.ts`: Drizzle over the Neon WebSocket driver (`drizzle-orm/neon-serverless`), pool created lazily on first use from `DATABASE_URL`.
- `src/studio/db/schema.ts`: tables in the Postgres schema `studio` (`pgSchema("studio")`).
- `src/studio/db/status.ts`, `src/studio/storage/blob.ts`: the shell's status checks; `blob.ts` is the private Vercel Blob helper.
- `src/studio/marker.ts`: `STUDIO_SERVER_MARKER`, imported by the data layer so the leak check can spot studio code in public output.
- `drizzle.config.ts`, `drizzle/`: drizzle-kit config and the committed SQL migrations.
- `scripts/migrate-on-build.mjs`, `scripts/check-studio-leak.mjs`: run inside `npm run build`.

## Rules

- Retention writes use the shared workspace advisory lock from `src/inquiries/db.ts`, then lock the parent client and included child rows. They deliberately support archived targets rather than calling the ordinary live client write guard. Keep full precision versions and recheck the complete snapshot, holds, relationship blockers and expiry inside the removal transaction.
- Retention due dates use archive time plus 12 calendar months in UTC. A server preview is bound to its workspace and actor, expires after ten minutes, and needs both the posted acknowledgement and exact `DELETE` confirmation. Removal is capped at 1,000 total rows and commits its aggregate receipt atomically; retries return the same unexpired receipt.
- Client retention removes only eligible clients, their contacts and their associated notes; independent contact removal preserves unrelated client notes. Contracts, projects and source inquiries block removal, and business records and immutable contract history are never deleted by retention. Inquiry cleanup remains separate.
- Retention metadata cleanup runs on use, at most 1,000 expired previews and 1,000 expired events per visit in the current workspace. Receipts last 12 calendar months and hold audit events record reason codes. Preview, receipt and audit rows contain identifiers and counts rather than copied personal content; do not add names or note text.
- Only the retention list has a Suspense loading fallback. Do not add a route wide `loading.tsx`: streaming before a resource lookup finishes turns its not found response into HTTP 200. Missing or inaccessible record, preview and receipt pages must return 404. The retention error screen reloads the document on retry so it does not reuse a failed server response.

- Every signed in studio layout, page, route handler, and server action calls `await requireStudioAccess()` before reading or writing anything. Only the studio root layout, the login and setup pages, and their actions call `requireStudioEnabled()` instead. The proxy alone is never enough (server actions can be POSTed to any path).
- Only the proxy refreshes the session cookie; only server actions create or clear it. `getStudioSession()` never writes cookies.
- Every module in `src/studio/` that touches a connection, a secret, or data starts with `import "server-only"` and imports `@/studio/marker`. Two exceptions: `db/schema.ts` skips `server-only` because drizzle-kit loads it outside Next (table shapes only, never a connection), and `auth/cookie.ts` skips it because the proxy imports it (names and flags only, never a secret). `contracts/markdown.ts`, `contracts/placeholders.ts`, and `contracts/values.ts` also skip it, because the client template editor shares them (pure code, no data or secrets).
- Studio may import shared UI from `src/components/`; public code never imports from `src/studio/`.
- No studio variable uses the `NEXT_PUBLIC_` prefix. The variable names are listed, empty, in `.env.example`.
- Never render a Blob URL to the browser; contract PDFs are read only through guarded server code.
- Migrations are forward only and additive (add, backfill, then remove in a later migration), because they run unattended in the Vercel build. Every table and the journal (`studio.__drizzle_migrations`) live in the `studio` schema. Add tables with `npm run db:generate`, apply locally with `npm run db:migrate`.
- Seed and preview data stay fake; no real client data in the repo or in preview branches.
- Studio server actions take `(prev: ActionState, formData)` and return `ActionState`. `requireStudioAccess()`, `redirect()`, and `notFound()` sit outside the `try`, so their control flow errors are never caught. An unexpected failure logs only the action name and the error `code` or class name; typed values come back only in `values` and are never logged.
- `next.config.mjs` sets `logging.serverFunctions: false`, because Next 16 dev logs each server action call with its arguments (which echo typed contact details). Keep it off.
- Every edit is versioned: read `updated_at::text` (full microseconds, never a JS `Date`), send it as the hidden `version`, and update `where updated_at = $version::timestamptz`; zero rows means `StaleRecord`.
- Every write on a contact, project, or note runs in a transaction that calls `lockLiveClient(tx, clientId)` first (lock order client, then child; throws `ClientArchived` for an archived client). Child reads and writes match `id`, `client_id`, and `workspace_id` together; an archived child counts as not found.
- Translate unique violations with `pgErrorOf()` / `isUniqueViolation()`, which unwrap Drizzle 0.45's `DrizzleQueryError` to the Postgres error; never read `err.code` directly. Pages pass caught errors to `notFoundOr()` so a `NotFound` shows the not found page and anything else reaches `error.tsx`.
- A contract's body and fields change only while it is `draft`. Its status moves only through `applyStatusStep()` in `data/contracts.ts`, one step from `CONTRACT_TRANSITIONS`, with exactly one status event. Every contract write checks, in order: not found, `ContractArchived`, `ClientArchived`, then the step or edit rules.
- Contract files are written put first, transaction second: the bytes go to private Blob at `ws/<workspaceId>/contracts/<contractId>/<fileId>.pdf` (never overwritten), then one transaction records the `contract_files` row. On a failure after the put, the Blob file is deleted only when no row with its id committed.
- `contract_files` is append only (a trigger rejects update and delete), like `contract_status_events`. No seed or reset script may delete its rows; reset a dev branch from its parent instead.
- Files are served only by the `pdf/` and `files/[fileId]/` route handlers, which stream from Blob with `Cache-Control: private, no-store` and `nosniff`. Generated PDFs are `inline`; uploaded signed copies are always `attachment`. Links use file ids, never a Blob URL or pathname.
- Signed copy uploads are capped at 4 MB, checked in the browser and again on the server (size plus the `%PDF-` magic bytes), because Vercel rejects requests over about 4.5 MB; `next.config.mjs` sets the server action body limit to `4.5mb`.
- `next.config.mjs` traces `src/studio/contracts/pdf/fonts/**` into every `/studio/**` route (`outputFileTracingIncludes`). The fonts are read from disk at runtime, so only a production build proves the tracing. `@react-pdf/renderer` is already on Next's default server external list.
- An invoice's fields and lines change only while it is `draft`; the triggers `invoice_lines_draft_only` and `invoice_frozen_fields` enforce this in the database, and `invoice_status_events` and `invoice_files` are append only. Invoices are never deleted; a draft is discarded by archiving it. Status moves only through `applyInvoiceStep()` along `INVOICE_TRANSITIONS`, each step posting the status it was shown from.
- Invoice numbers (`INV-<year>-<n>`, per workspace and issue year) are taken only at send: peek the next number, render and put the PDF, then `takeNumber()` inside the send transaction and compare; a mismatch retries the send once. A rolled back send leaves no gap. The frozen PDF follows the contract files rule (put first, transaction second, delete only when no row committed) at `ws/<workspaceId>/invoices/<invoiceId>/<fileId>.pdf`.
- Invoice writes lock client, then contract, then invoice. Archiving a contract or a client refuses while it has a `sent` invoice. Line amounts must equal the half up rule in `money.ts`, which a database check repeats; keep the two in step (`money.test.ts` compares them).
- `invoices/money.ts` skips `server-only` like `contracts/markdown.ts`, because the client invoice form shares it (pure code, no data or secrets).
- Every invoice read goes through `invoiceRead()` in `invoices/read.ts`, so Next never logs a Drizzle error's SQL or parameters for these pages; keep new invoice reads wrapped.
- `getStudioSession()` rethrows a failed lookup as `SessionLookupFailed`, carrying only the Postgres code, because the Drizzle error holds the session token hash as a parameter. A thrown lookup still reaches the outage screen (`studio/error.tsx`, spec 0012); keep any new session query inside that `try`.
- `data/contracts.ts` loads the PDF renderer with a dynamic `import()` only when it renders: `tsx` (the seed) cannot load react-pdf's ESM only parts. In react-pdf, place fixed footers with `top`; this version does not draw a `bottom` offset.
- The public `utils/data/products-data.ts` is generated by the systems export, never hand edited: `buildPublicProductsFile()` reads only `getPublicProjection()`, which selects public columns of published, live systems and links whose two ends are both exported. Never add a private column to that query. The file's types, `statusSections`, and header are written literally in `systems/export.ts`, so change them there, then export again.
- `systems.standalone` always equals `layer = 'standalone'` (a database check); the data layer derives it from `layer` and forms never set it. `systems.published` defaults to off for a new system and the import never changes it. A system's id (the public slug) never changes after create.
- Archived systems are read only, the import skips them, and the export leaves them and their links out. Link writes lock both ends with `lockLiveSystem()` in sorted id order and need both ends live.
- The import never deletes, plans again inside its own transaction (never trusting the preview), writes creates as one multi row insert per table, and sets `lock_timeout`, `statement_timeout`, and `idle_in_transaction_session_timeout` first: Vercel kills a request at its time limit and can leave its transaction open, which blocks the next try. The import page sets `maxDuration = 60`. The pasted JSON holds private data: never log it and never commit it.
- Inbox search never puts a term in the URL (request logs keep URLs, and a term is often a visitor's name or email). The search form posts to `searchInquiriesAction`, which stores the term in the `studio_inquiry_q` cookie (`inquirySearchCookieOptions()` in `auth/cookie.ts`: `httpOnly`, `sameSite: strict`, path `/studio/inquiries`, 30 minutes). A `?q=` in the URL is ignored.
- An inquiry's submitted content never changes. Status moves only along `transitionAllowed()` with a version check and one `inquiry_events` row. Conversion is deliberate, runs in one transaction, links the inquiry to exactly one client (a new Lead or an existing client), and a repeated conversion never creates a second client.
- Forms key on `stateKey(state)` from `FormMessage.tsx` so they remount on each action result; React 19 resets a form after its action, and a `<select>` would otherwise fall back to its first option.

## Local env

- `.env.local` (from `vercel env pull`) holds `STUDIO_ENABLED` and `BLOB_READ_WRITE_TOKEN`.
- `STUDIO_ENABLED` is on in Development and Production, never Preview (spec 0005). When it is off, every `/studio` URL is a bare 404 from the proxy, which is what an unset Production variable looks like.
- Login needs `STUDIO_RP_ID` (the passkey domain) and `STUDIO_ORIGIN` (the exact browser origin): `localhost` and `http://localhost:3000` locally. In Production the leak check fails the build unless both are set, the origin is `https://`, and its host matches the RP ID. An `https://` origin switches the cookie to `__Host-studio_session`.
- `STUDIO_SETUP_TOKEN` (at least 32 characters) is set only while enrolling or recovering a passkey at `/studio/setup`, then removed (redeploy both times). The leak check scans for it when present.
- The Neon dev branch URLs (`DATABASE_URL`, `DATABASE_URL_UNPOOLED`) live in `.env.development.local` on purpose, so a local `next build` never sees a database. Never pull `DATABASE_*` into `.env.local`. `drizzle.config.ts` loads env in dev mode so drizzle-kit picks up this file.
- A local `npm run build` never migrates. The leak check logs which secrets it skipped locally; on Vercel a missing studio secret fails the build.
